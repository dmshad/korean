## Архитектура

- Один артефакт, режимы (меню справа от поиска, режим запоминается):
  Словарь / Грамматика / Тема (Слова | Грамматика) / Повторение (Слова | Грамматика | Числа | Формы) / Диалог (Переписка | Разговор) / Прогресс.
  Последняя строка меню — тумблер «Автономный режим» (двойное нажатие, без перезагрузки; см. «Автономный режим»).
  В «Повторении» направление — сегмент с явными кнопками (`#dseg`, вместо переключателя по кругу):
  слова и грамматика — РУС→КОР | КОР→РУС | 🔊 На слух; «Числа» — Цифры→КОР | КОР→цифры | 🔊 На слух;
  «Формы» — По словарной | По переводу. В «Теме» — прежняя кнопка РУС↔КОР.
  Вкладки «Числа» и «Формы» видны только в «Повторении».
- Опубликованная страница по ссылке, открывается с айфона. Офлайн не нужен.
- Один HTML-файл: в начале блок JSON-данных `<script id="data">`, ниже код.
  Новые слова = правка блока данных, код не трогается.
- Капабилити страницы: **db** (состояние тренажёра), **sample** (запросы к Claude
  из страницы, из лимитов ученика). При публикации передавать обе: `{db:{}, sample:{}}`.
- Состояние тренажёра: db-документ `trainer/state` + копия в localStorage;
  при загрузке берётся более свежая. Тестовый автономный режим внутри Claude: `trainer/state_off`
  (+ localStorage `trainer_off`), флаг режима — db `trainer/mode {off}` (+ localStorage `offmode`).

### Структура данных (зафиксирована, не менять)

`meta{version, currentBlock, currentGrammar}` · `blocks[{id,label,order}]` · `notes{nN: текст}` · `words[]` ·
`grammar[]` · `morphs[]` · `conj{}` · `drill{}` · `bank{}` · `dlg[]` (с 03.10). meta.version = 2.

Готовый диалог `dlg[]`: `{id: dNN, sit (ключ DSIT), after: N (номер грамматической темы — открывается, когда gN пройдена или текущая), scene, partner,
lines[{s:'p', ko, ru, tip} | {s:'me', ru (контекст в скобках), ko (шаблон), alt[], traps[{a,why}], tip}]}`.

Запись слова:
- id (омонимы: 일-1/-2/-3), ko, tr, pr (хангыль-чтение, скрытое), ru, cat, sub, tag,
  block, weak
- usage — только где значение расходится с русским и это не покрыто заметкой
- notes[] — id заметок раздела 3 файла
- rel[{id,t}] — t: homonym / pair / register / see; связи всегда двусторонние
- roots[{s,m}] — слоги 한자어; слова с тем же корнем находятся по паре s+m,
  поэтому одинаковый слог с другим значением получает другое m
- forms{pres,past} — глаголы и 형용사
- ex[{ko,ru}] — 2–3 примера
- extra

Тема грамматики `grammar[]`:
- id (`g1`…`g46`), n, title, meaning (абзацы через \n, **жирный**)
- schema[{title, cols[], rows[[...]], note}] — таблицы; в ячейке « · » = перенос строки
- sections[{id: sN, title, body, ex[]}] — разбор
- usage[{id: uN, sit, phrase, note, ex[]}] — ситуации употребления (главный упор)
- rel[{id, label?}] — темы (gN) и морфемы (по id); label — подпись, пока цель не создана
  (серая ссылка). Связь тема → морфема дублируется в морфеме автоматически при сборке.
- new[] — id разделов/ситуаций с флагом «не отработано»
- parts[{id, title, intro, schema[], sections[], usage[], ex[[{ru,ko,alt[],u}×5]]}] — части урока:
  intro — суть части (свой короткий «смысл»), schema — индексы таблиц темы, относящихся к части;
  базовые блоки пишутся заранее. Правило деления: одна часть — одна форма/функция; совмещение
  (например, 도 и 만 после 에/에서) — отдельной частью после частей по каждой форме.
  Смысл и схема всей темы — на стартовом экране и по кнопке «Вся тема целиком»; allEx[[…×8]] — базовые блоки этапа «Вся тема». Темы 1–13 без частей.
- open: true — тема изучается; в повторение грамматики не идёт, пока флаг не снят.

Морфема `morphs[]`: id (= форма: `은/는`, `-지 않다`), kind (particle / ending / adverb),
forms[{c: условие, f: форма, ex}], func, usage[] (как у тем), ex[], topic (n), rel[], new[].

Спряжение `conj`: stems[{id,label}] (строки — типы основ) · forms[{id,label}] (колонки) ·
cells{"stem|form": {v, ex, topic}}.

Банк заданий `bank` (автономный режим):
- `bank{gN: {qN | _: [фраза]}}` — пул на часть темы (qN) или на всю тему без частей (`_`, темы 1–13).
- Фраза: `{ru, ko, alt[], traps[{a, why}], u, strict?}`. `ko` и `alt` — шаблоны: `( )` — необязательно,
  `[a|b]` — варианты; на экране `ko` сворачивается (скобки — с содержимым, из вариантов — первый),
  шаблон уходит в alt. `traps` — типичные НЕВЕРНЫЕ ответы с пояснением. `strict: true` — задание требует
  конкретную форму («длинной формой отрицания»): правила равнозначности для него отключены.
- Пул части = bank + базовые блоки части (ex, allEx по модели) — сборка кодом, дубли по показанной фразе.
- Базовые блоки (parts.ex, allEx) тоже можно писать шаблонами — показываются свёрнутыми.

Повторение грамматики `drill`:
- weak[] — пусто. Грамматические слабые места не отслеживаются (решение ученика): ровное
  покрытие тем достаточно, реальные пробелы — перечитать теорию / «Почему?». Разовая
  отработка конструкции — по команде «добавь в повторение фразы на X».
- skip[] — id слов, не идущих в повторение грамматики: 시, 분, 요일, 월, 일-2, 년
  (время и даты — тема 16).

## Ведение: где и как

Справочник обновляется **только в чате «справочник»**. Учебные чаты его не трогают.

**Начало словарной темы:**
1. Словарный чат перед разделом 1 выдаёт одним копируемым блоком все 20 слов темы,
   разбитые на блоки справочника по 5, в формате подачи (`사과 [сагва] — яблоко`).
   Номера блоков продолжают хронологию ниже.
2. Ученик вставляет блок в чат «справочник» с командой «добавь тему N».
3. Справочник: добавляет слова со всеми полями, ставит `currentBlock` на последние блоки темы,
   перепубликует по ссылке. Режим «Тема» тренажёра сам перестраивается на новые блоки.

**Закрытие темы:**
1. Словарный чат обновляет korean_learned.md (как раньше).
2. В чате «справочник» — «закрой тему N»: сверка с файлом, «плохо помню» → weak,
   метка «текущая» снимается.

Почему в файл не вносятся слова в начале темы: завышается прогресс (слова считаются
по строкам реестра), и слова текущей темы попадают в пул Б смешанных как «старые».
Приложение прогресс не считает — только файл, только при закрытии темы.

**Подготовка грамматической темы («подготовь грамматику N»)** — ДО изучения, после закрытия
предшествующей словарной темы: карточка темы с частями (parts), базовые блоки (по 1–3 на часть,
1–2 «вся тема»), `open: true`, `meta.currentGrammar = gN`. Примеры и блоки — на лексике,
доступной к этому моменту. Далее всё, что ниже, кроме FORBID.
Плюс банк темы (`bank.gN.qN`): 30–45 фраз на часть с шаблонами и ловушками, прогон проверкой
(каждый вариант принимается, каждая ловушка ловится), проверка лексики по словарю.

**Закрытие («закрой грамматику N» в справочнике, после итога в учебном чате):** снять `open`,
убрать конструкции темы из `FORBID`, снять флаги по итогам. Если снятые флаги открывают модели
старых тем — дописать фразы на них в пулы `bank.gN._`.

**Добавление грамматической темы (старый порядок, «добавь грамматику N»):**
карточка темы, новые морфемы, строки/колонки спряжения, связи, флаги — и обязательно:
- убрать конструкции темы N из списка запрещённого `FORBID` в коде повторения грамматики
  (иначе генератор их не даст). Пример: тема 15 → убрать 에게/한테, 부터/까지;
- при теме 16 — `drill.skip` и `FORBID` время/даты снимаются кодом по позиции (с 01.10);
- при теме 18 — запрет форм ㅂ-불규칙 снимается кодом по позиции (пара g18 в `T`, с 01.10); `BPU` (исключение ㅂ-слов из «Форм» и курса «на слух») пустеет, если g18 в данных.
Новая тема и снятые флаги попадают в повторение автоматически (читаются из grammar[]).

**Правила заданий (генерация Claude, базовые блоки, банк) — решено 30.09:**
- Задание из нескольких фраз — одна связная мини-ситуация: вопрос → ответ, утверждение → уточнение.
- Контекст — только в скобках, одна короткая скобка и только если без неё выбор формы неоднозначен.
  Указания («спроси…», «скажи…», «ты посмотрел фильм…») — только в скобках; вне скобок — ровно то,
  что переводится. На экране скобки — серым курсивом.
- Счёт: исконные числа — с 개, 명, 마리, 잔, 권, 살, 시; китайские — с 원, 층, 분, 번, номера, даты.
- Ловушки — только настоящие ошибки. Верное, но редкое/книжное (무엇이, 보았어요, 마시었어요),
  спорное разговорное (часть суток без 에: 저녁 집에서 쉬어요) — не ловушка: уходит в «не распознано».
- Не использовать конструкции будущих тем: 제/내 и опускание 의 (민수 전화번호, 회사 주소) — тема 15;
  время и даты — тема 16; слова вне словаря (러시아, 부) — нельзя, даже в alt.

**Решено 01.10 (применить с темы 15):**
- Эталон показывается **всегда**, и при верном ответе (с озвучкой). ✅ Сделано 01.10 (.16): «Эталон: … ▶» под каждым верным ответом РУС→КОР, у фраз банка — шаблон со скобками (`tplK`), озвучка — без скобок.
- Необязательная частица в эталоне — в скобках: 여기(는) 커피(가) 싸요, 친구(의) 이름 — подразумевается,
  в речи часто опускается. Показ шаблона со скобками как есть (не раскрывать). Ответ ученика со скобками
  принимается (проверяется вариант с содержимым скобок); писать скобки не обязательно. Уже сделанное не переписывать.
- Задания: «여기에 + 형용사» (여기에 커피가 싸요) — кальна; «здесь X …» о свойствах — 여기(는).

**Правила обогащения новых слов:**
- usage — только расхождение с русским, без дублей с заметками.
- rel — пары, регистровые двойники, «см. также» — в том числе к старым словам.
- roots — для 한자어, значение слога согласовано с уже размеченными.
- forms — 해요 и прошедшее.
- ex — изученные слова + слова текущей темы, грамматика только пройденная на момент
  написания. При прохождении новой грамматики не переписываются (исключения — в хвостах).

**Перенос между окнами:** ссылка → Artifact read → правка → publish по той же ссылке
с `capabilities: {db:{}, sample:{}}`.
**Ведение с 01.10 (учёба в автономной версии):**
- Тема закрывается в приложении («Прогресс → Курс → Тема пройдена»); ученик вставляет в чат «Итог темы» —
  по нему обновляется korean_learned.md. Прогресс ученика в Claude не виден (живёт в телефоне).
- Новая тема выкладывается целиком (слова со всеми полями / теория, части, базовые блоки, банк) — генерации
  в приложении нет. Выкладка партиями: правка артефакта → publish → сборка пакета → push (см. «Доставка»).
- Флаги «не отработано» и `open` больше не снимаются вручную: их ведёт курс (см. «Курс»).

**Перед publish (обязательно, в каждом чате):** `Artifact read` в ТОМ ЖЕ ходе, что и publish;
правку применять к только что прочитанному файлу. Файл, прочитанный раньше в разговоре, —
устарел: его не публиковать. После read сверить, что на месте меню «Диалог», вкладки
«Числа | Формы», сегмент направления `#dseg`, тумблер `id="offb"`, экран «Прогресс» (`function renderP`),
банк (`"bank":` в данных), курс (`const COURSE=`, `function courseHTML`, `"course":` в данных) и памятки
(`"memos":`) — иначе publish затрёт чужую работу.
Регрессии уже были дважды: 25.09 и 26.09 (второй раз правка частиц в скобках из другого чата
опубликована поверх старой копии — затёрты Диалог, Числа, Формы, на слух; восстановлено

Ошибок и слабых мест в карточках нет.

- Теория пишется заново, подробнее исходной. Справочник — эталон пройденных моделей:

- Примеры — только лексика и грамматика, пройденные на момент темы. Не переписываются.

## Тренажёр слов (работает)

**Тема** — текущая словарная тема (блоки `currentBlock`). Этапы: Раздел 1…N (по блоку) →

(пул А: слова темы ×2 + 10 добором; пул Б: 50 из реестра; блок 5 + 5).
Переход между этапами — кнопкой «Дальше».

**Повторение → Слова** — 100 слов реестра (без текущей темы), пропорционально категориям,
«плохо помню» первыми, слова прошлой серии — в последнюю очередь; 10 блоков по 10.

Механика (направления независимы — см. «Повторение грамматики»): РУС→КОР — ввод с проверкой и разбором по чамо, кнопка «Опечатка»;

(для слов текущей темы метка не ставится). Ошибки блока повторяются в конце блока.
Стык блоков соблюдается. В конце серии — охват.

**Итог словарной темы:** последний чип этапов «Итог темы» → текст для словарного чата
(«закрой тему N»): этапы, ответы по словам темы, «плохо помню» — слова темы и остальной словарь.
Слова темы учитываются отдельно (`ST.tw[THEME]`): ошибка или подсказка ставит метку, 2 верных
подряд снимают; в общий weak не идут до «закрой тему N» в справочнике (там переносятся в weak).

## Урок грамматики (каркас, тестируется на теме 14)

Режим «Тема → Грамматика», текущая тема — `meta.currentGrammar` (сейчас **g15**; g14 была тестом каркаса).

**Этапы:** Часть 1…N → Вся тема (блоки по 8) → Смешанные РУС→КОР (10: 5 по теме + 5 старых) →
Смешанные КОР→РУС → Итог. Чипы этапов вверху; переход — «Дальше: …» после проверки блока.
Части: экран теории (суть части, её таблицы, разделы, употребление; кнопка «Вся тема целиком»),
«К упражнениям» → блоки по 5 на моделях части, «Ещё блок» без ограничения, «Теория части».

**Блоки:** сначала базовые из данных (готовы сразу), дальше генерация через sample. Разрешено:
темы до текущей + части текущей темы до текущей включительно. Слова: 2–3 из последней
закрытой словарной темы по кругу + остальные из реестра без повторов.

**Очередь:** «Начать тему» → в фоне готовится по этапам: база + 1 блок (части, вся тема),
2 блока (смешанные). Последовательно, пока страница открыта; продолжается при открытии.
Сбой блока в очереди — пропуск, догенерация по месту.

**Вопросы:** «Почему?» у ошибки (и в повторении) — объяснение от Claude, сохраняется в блоке.
«Вопрос по теории» на экране части — ответы хранятся по частям. В справочник не попадают.

**Итог:** этапы с результатами, ошибки по типам, список ошибок. Текст копируется в учебный чат: «закрой грамматику N».

**Состояние:** `ST.les{g, stage, view, by{этап: сессия}, qa, started, wq, cp}`; при смене
currentGrammar сбрасывается.

**Практикум (решено):** оформляется как обычная тема с частями, без номера в плане.

не показывается; `label: "Практикум 1"` — вместо «Тема N»; `norev: true` — в повторение
грамматики не идёт (его модели принадлежат темам 1–14 и попадают туда после снятия флагов).

**Слова — курс тем на слух** (состояние `ST.au {cur, view, done, by{тема:{stage, s{этап}}}, st{id:[ok,bad]}}`):
- Деление строится кодом при загрузке: база (+네/아니요) в порядке категорий местоимения →

## Диалог (тестируется)

Отдельный режим меню «Диалог», две вкладки — симулятор переписки и живого разговора.
Обе на одном движке «диалог по репликам» (код `tr*`, состояние `ST.dlg.tr` и `ST.dlg.vo`,
очереди и серии у вкладок раздельные). Уровней сложности нет.

**Переписка** (`tr`): Claude заранее составляет связный диалог 8–12 реплик (сцена, роль, реплики
`p` — собеседник: ko + ru; `me` — ученик: ru с пояснением в скобках + ko + alt + tip). Ученик по очереди
переводит: реплики собеседника видит текстом и переводит КОР→РУС, свои — РУС→КОР. Каждый ответ —
отдельный короткий sample (сцена + предыдущие реплики, без словаря): ok / typo / bad + fix + note + tip;
«Не знаю» / «-» — эталон без запроса. После ответа — эталон, «Засчитать / Не засчитывать».
«🔊 Авто» — озвучка реплики собеседника при появлении.

**Разговор** (`vo`): то же, но реплика собеседника не показывается — только кнопка «🔊 Слушать»
(сколько угодно раз, автопроигрывания нет), ученик пишет перевод на русский. Текст реплики
открывается после ответа. Ползунок скорости 0.1–1.2 (`ST.rate`, общий для всей озвучки).
Свои реплики — как в «Переписке».

Следующий диалог готовится в фоне (очередь 1). Итог — «верно X из Y».
Состояние: `ST.dlg {sit, tab: tr|vo, auto, lastSit, tr{…}, vo{…}}`, где
`{q[], cur{id,sit,scene,partner,lines[],i,res{k:{t,v,fix,note,tip}}}, n, want}`.
Прежние вкладки (свободный «Разговор» с ролью Claude, «Аудирование» подряд) убраны 26.09.

Ситуации: Любая · Знакомство · Магазин · Кафе · Договориться · Телефон и адрес ·
Разговор о дне · Семья (`DSIT`/`DSITD`; «Любая» — случайная, не повторяя прошлую).
Адрес — только спросить / попросить записать, не диктовать (настоящий адрес пройденной
лексикой не выразить).

Ограничения для Claude — общие (`dRules`): грамматика GTOP + текущая тема (CURG) целиком,
`FORBID` (минус 누가/뭐가, если в частях CURG есть unflag g2:u9), флаги «не отработано»
за вычетом unflag частей CURG, весь словарь кроме currentBlock и drill.skip, стиль 해요
(반말-формулы 안녕/고마워/미안해 запрещены), имена 민수/지민 — одно имя в сцене, роли и
репликах, «ученик — мужчина». Пояснения в скобках — коротко, не повторяя фразу; реплики —
то, что реально говорят, без кальки с русского. Модель — `DTIER='default'`.

**Живая речь, не учебник:** общепринятые разговорные упрощения разрешены и предпочтительны
в эталонах (опущенные 저는/тема, выпадение 이/가 и 을/를, 어디 가요? без 에, ответ-обрывок
без связки — 오 층, 커피; N(이)요 — 칠팔구공이요; дефис в номере как 에). Полная учебная
форма — в alt и тоже засчитывается. Правило только для «Диалога»; в повторении и уроках
грамматики — прежнее (частицы в эталоне не опускать).

**Пояснения (жёлтая плашка):** «Живая речь: …» у реплики с упрощением (полная форма, что
опущено, почему так говорят); совет к верному ответу ученика, если носитель сказал бы
короче/естественнее («как говорят: …»). Поля `tip` у реплик и результатов.

### Проверка без Claude (РУС→КОР)

1. **Шаблон эталона** вместо списка alt: `(저는) 학생이에요`, `[어디에서|어디서] 왔어요?` —
   ( ) необязательно, [ | ] альтернативы; код раскрывает сочетания. При генерации варианты —
   исчерпывающие (опущенная тема, выпадение частиц, порядок, синонимы).
2. **Нормализация:** пунктуация, пробелы, регистр (для греческого — опция «ударение не учитывать»).
3. **Ловушки:** к каждой фразе 2–4 типичных неверных ответа с пояснением «почему так нельзя».
   Совпадение с ловушкой → её пояснение.
4. **Правила кода** для механических ошибок: алломорф частицы (은/는, 을/를, 이에요/예요 —
   пояснение по 받침), запись по произношению (머거요), пропущенное 요 и т.п.
5. **Неопознанный ответ:** подсветка отличий, суть модели, ссылка на раздел теории; вердикт
   ставит ученик («Засчитать» / «Моя ошибка»); ответ — в список **«Спорные»**.
6. **Дообучение банка:** в режиме Claude «Спорные» пакетом уходят на проверку; верный ответ
   → вариант шаблона, неверный → ловушка с пояснением. Без Claude «Спорные» выгружаются
   файлом, обновлённый банк приходит с новой версией приложения.

КОР→РУС — самопроверка: ввод перевода → эталон → «верно / неверно».

## Технические ограничения (выяснено)

- Опубликованная страница самодостаточна: внешние файлы и сеть заблокированы.
- Прямой fetch к API из опубликованной страницы не работает. Вместо него — capability
  **sample** (`claude.use('sample')`): запрос к Claude из лимитов зрителя, разрешение
  спрашивается при первом вызове. Работает только при открытии страницы в Claude.
- Капабилити объявляются при publish; непустой объект заменяет весь набор —
  всегда передавать полный: `{db:{}, sample:{}}`.
- Лимит страницы 16 МБ; словарь на финише (800 слов) — под 1 МБ.
- Лимит запроса sample — 64 КБ; запрос генерации сейчас ~27 КБ (растёт со словарём
  и темами — следить).
- `:has()` в CSS — iOS 15.4+.
- Системные окна `confirm()` / `alert()` в артефакте заблокированы молча — подтверждения делать
  двойным нажатием на странице.
- Приложение Claude на iOS не сохраняет localStorage артефакта между запусками — постоянное
  хранение внутри Claude только через db. На хостинге (PWA с экрана «Домой») localStorage постоянен.
- Внутри Claude файл не скачать и не отдать через share — только текст для копирования.
